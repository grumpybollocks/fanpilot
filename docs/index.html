What it is

FanPilot is a fan controller for Linux desktops. A small root service (Python standard library only) drives the motherboard's fan headers through the kernel's hwmon drivers and the graphics card's fan through its own interface, and an ordinary desktop app with a tray icon lets you choose Automatic, a fixed speed or a temperature curve for every fan. It names the headers the way the board does where it knows the board, warns you when a fan stalls, and hands every fan back to the BIOS or the card's firmware whenever it stops, crashes or is killed. A fresh install changes nothing: every fan starts on Automatic.

🔌

Driver helper

For boards with an ITE chip, one script sets up the it87 driver (DKMS, rebuilt on kernel updates). Every step is printed and can be undone.

🏷️

Real names

On boards FanPilot knows: CPU_FAN, SYS_FAN1, ... instead of pwm2 and temp5. Rename anything yourself.

🎮

GPU too

AMD RX 7000 / 9000: the fan curve is written into the card's own firmware.

🛟

Fail-safe

Starts on Automatic and changes nothing until you choose. Hands everything back on any failure.

Features

Simple by default, detailed when you want it.

📈 Drag-and-drop fan curves

Each fan can be Automatic (BIOS or card decides), a fixed speed, or a temperature curve.

  • Drag points; double-click to add one, right-click to remove one
  • A live marker shows the current temperature and speed
  • Case fans can follow the hotter of CPU and GPU, so they also help while the GPU is busy
  • Fine tuning: lowest speed, allow stop, smoothing, ramp limits

🎮 Graphics card curve in firmware

For AMD RX 7000 / 9000 cards with OverDrive enabled, FanPilot writes your curve into the card itself. It keeps working even if FanPilot is stopped, and zero-RPM (fan off when cool) is your choice.

  • Follows the GPU hotspot temperature
  • Every write is read back and checked
  • Automatic hands control straight back to the card

🎛️ Profiles, limits and a one-click self-test

Silent, Balanced and Performance are built in, and you can save your own. Switch from the top of the window, from the tray icon, or from the command line.

  • Self-test button: ✔/✖ for the chip, sensors, speed control, crash recovery and GPU curve (about 45 s, no password)
  • Emergency limits: above them every motherboard fan runs at full speed
  • Built-in profiles keep each fan's measured lowest speed

📋 Every sensor, HWiNFO-style

One table grouped by device: CPU, motherboard, graphics card and drives. Temperatures, voltages, clocks, power, load and fans, each with Current, Minimum, Maximum and Average. Values past a limit turn red. Reset, copy, export or log to CSV.

🔍

Identify

Runs one header slow for 3 s, then at full speed for 3 s, so you can see or hear which physical fan it is.

📏

Calibration

Measures where each fan stops and restarts, then never asks for less than that.

🗺️

Map my fans

Finds which header drives which fan and hides headers with nothing connected (about 15 s per header).

🚨

Stall warning

Desktop alert (while the app or tray runs) if a fan stops while it should spin.

🖥️

Feels native

Follows your desktop theme (light/dark), lives in the tray, and only one copy runs at a time.

🔔

Your own alarms

Right-click any sensor: get a desktop notification when it goes above or below your value.

🔢

Value on the tray

Right-click any sensor → Show on tray icon: that number sits in your panel.

📄

Sensor file

/run/fanpilot/sensors.tsv (in RAM, rewritten once a second) for other programs, e.g. the Logitech G510 keyboard LCD app.

💾

Backup & restore

fanpilotctl config > my-fans.json and fanpilotctl import my-fans.json.

Supported hardware

FanPilot only writes to drivers it knows to be controllable. Everything else is shown read-only.

Motherboard fan chips

DriverTypical boards
ITE it87 (in-tree, or the newer frankcrawford/it87)most Gigabyte, some ASRock and older boards
Nuvoton nct6775 familymost ASUS, many MSI and ASRock boards
Nuvoton nct6687 (nct6687d, out-of-tree)newer MSI boards
Fintek f71882fg family
Winbond w83627ehf family
Read-only: nct6683, asus-ec-sensors, asus_wmi_sensors, gigabyte-wmi, hp-wmi-sensors, any other chipshown in the Sensors tab, never written to

Boards FanPilot knows get the headers' printed names (CPU_FAN, SYS_FAN1, ...). Any other board works generically ("Fan 1", "Fan 2", ...), and every motherboard fan gets the CPU fan's protection until you tell FanPilot which one the CPU fan is.

Graphics cards

CardWhat FanPilot does
AMD RX 7000 / 9000 with OverDriveTemperature curve stored in the card's firmware (5 points), zero-RPM optional
AMD RX 7000 / 9000 without OverDriveShown read-only, with a hint: add the OverDrive bit (0x4000) to the amdgpu.ppfeaturemask kernel parameter
AMD up to RX 6000Beta: controlled like a motherboard header; handed back to the card on every exit
NVIDIA (proprietary driver)Read-only temperature and fan % through nvidia-smi; it also counts for the GPU emergency limit
NVIDIA nouveau, IntelRead-only, as far as the kernel reports anything

Laptops (Dell, ThinkPad, ...) are read-only; use thinkfan or nbfc-linux for their fans.

Install

Linux with systemd and Python 3.10+; the app also needs PySide6. Each script prints what it does and can be undone. Full guide: docs/SETUP.md.

Packages (after the first public release)

Arch, Manjaro, EndeavourOS: AUR package fanpilot, app: sudo pacman -S pyside6. Debian 13+, Ubuntu 24.10+: the .deb; Fedora 43+: the .rpm, both from the GitHub releases page.

sudo usermod -aG fanpilot $USER          # then log out and in
sudo systemctl enable --now fanpilotd

Or from source (any distribution)

Runs the test suite first, then installs. Every fan starts on Automatic.

git clone https://github.com/grumpybollocks/fanpilot.git && cd fanpilot
sudo ./install.sh --autostart      # tray icon at login; undo: sudo ./uninstall.sh

No PySide6 package on your distribution (Ubuntu 24.04, Debian 12)? Add --gui-venv.

Motherboard driver (ITE boards)

Boards with an ITE chip (most Gigabyte, some ASRock) usually need the it87 driver set up. Nuvoton boards normally work out of the box; the graphics card needs nothing.

sudo scripts/install-driver.sh          # from a package: sudo fanpilot-install-driver; undo: --undo
scripts/install-driver.sh --dry-run     # see every step first, nothing is changed

First run

Open FanPilot from the app menu and check the Sensors tab. Optional: Settings → Run self-test (about 45 s). Then Identify and Measure each system fan (on an unknown board, right-click the CPU fan → This is a CPU fan), and pick a profile.

Command line

fanpilotctl status                      # fans and temperatures
fanpilotctl sensors [-w]                # every reading (-w: refresh every second)
fanpilotctl config > my-fans.json       # current config as JSON (backup)
fanpilotctl set <fan> auto|fixed|curve [value]
fanpilotctl calibrate [<fan>] [--stop]  # measure stop/start speed
fanpilotctl events                      # recent events
fanpilotctl map [--stop] [--forget]     # which header drives which fan
fanpilotctl report                      # anonymised hardware report for bug reports
fanpilotctl rename <id> [name]
fanpilotctl cpu-fan [<fan>...]
fanpilotctl identify <fan>
fanpilotctl profile list|apply|save|delete [name]
fanpilotctl selftest                    # about 45 s
fanpilotctl import my-fans.json

Safety first

FanPilot treats "a fan stopped when it shouldn't have" as the worst possible bug.

SituationWhat happens
The service stops, crashes, hangs or is killedEvery fan goes back to BIOS / GPU-firmware control (systemd restore step + watchdog), and systemd restarts the service
A fan's temperature sensor fails 3 readings in a row (3 s at the default 1 s interval)That fan goes to 100 %
CPU ≥ 90 °C or GPU hotspot ≥ 100 °C (adjustable)All motherboard fans go to 100 %, including fans on Automatic
The CPU temperature fails 3 readings in a rowAll motherboard fans go to 100 % until it reads again
The fan driver is reloaded, or a sensor appears late at bootFound again within 10 s
Another tool (e.g. LACT, CoreCtrl) resets the GPU curveRe-applied within 30 s (up to 3 times an hour); the tool is named in the log
FanPilot is updated while its window or tray icon is openThe app restarts itself as the new version; fan control is never interrupted
CPU fanNever below 20 %, never stopped
Other fansNever below 10 %, or below the measured lowest working speed, unless you allow them to stop
A fan stops while it should spinDesktop warning (while the app or tray runs)
The BIOS keeps taking a fan backAfter 5 times in a minute FanPilot leaves that fan on Automatic and tells you
The GPU firmware rejects a curveRetried after 60 s; after 3 failures the card keeps control
Invalid settingsRejected; the old settings stay in force
Fresh installEvery fan starts on Automatic, so nothing changes until you choose

How it works

A small background service does the work; the app is just a window onto it.

FanPilot app / fanpilotctlYour user. PySide6 window and tray. Talks to the service over a local socket; only allowed users may change settings.
fanpilotdRoot service (systemd), Python standard library only. Control loop (1 s by default), curves, profiles, safety rules.
MotherboardThe board's fan chip through its hwmon driver (it87, nct6775, nct6687, ...): PWM headers and board temperatures.
Graphics cardAMD RX 7000 / 9000: firmware fan curve (gpu_od/fan_ctrl), all points staged, then one commit. Older AMD: pwm1 (beta).
systemdWatchdog and a restore step after every stop, including crashes, so fans always return to the BIOS.

Everything is tested against a simulated sysfs tree that also emulates the GPU firmware's stage/commit rules: 216 tests, including real GUI widgets driven offscreen.

FAQ

Will it make my PC run hotter?

Only if you choose a quieter curve. The emergency limits still force every motherboard fan to full speed above 90 °C (CPU) or 100 °C (GPU hotspot), and a fan whose sensor can't be read goes to 100 %.

What happens if I uninstall it, or it crashes?

Every fan goes back to exactly what the BIOS and the graphics card do without FanPilot. The self-test checks this. Uninstall: sudo ./uninstall.sh (add --purge to delete /etc/fanpilot) and sudo scripts/install-driver.sh --undo if you used the driver helper; packages are removed with your package manager.

Does it work on other boards?

Yes, on any desktop whose motherboard fan chip has a Linux driver that allows control: ITE it87 (many Gigabyte, ASRock and older boards), the Nuvoton nct6775 family (most ASUS and many MSI, ASRock boards), Nuvoton nct6687 (newer MSI boards, out-of-tree driver), Fintek f71882fg and Winbond w83627ehf. Other chips are shown read-only, never written to. Boards FanPilot knows get the headers' real names; any other board works generically, and every fan gets the CPU fan's protection until you mark the CPU fan (right-click it → This is a CPU fan).

My motherboard fans are missing

FanPilot shows hints in the window, in fanpilotctl status and in the self-test. See My motherboard fans are missing and Troubleshooting.

My fans got louder after suspend

FanPilot re-applies your settings within a second after resume; the Log tab shows it.

How do I report a bug?

Attach fanpilotctl report > my-pc.json: it is anonymised, needs no root, and becomes a test machine for the fix. See CONTRIBUTING.md.
